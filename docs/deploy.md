# Deploying Acnologia

Acnologia is one container with one SQLite database. Every deploy option
below comes down to the same five things:

- **Persistent storage at `/data`.** The database lives there, and so does
  `master.key` when you do not set `ACNOLOGIA_MASTER_KEY`. Without a volume
  or disk, every redeploy starts empty and the stored keys are lost.
- **Exactly one instance.** SQLite is one file on one volume. Never scale out
  and never run two copies against the same data.
- **HTTPS.** Every platform here gives you a certificate; the VPS installer
  gets one from Let's Encrypt.
- **The access password on any public deploy.** It puts a lock screen in
  front of the whole site. See [Settings for any public deploy](#settings-for-any-public-deploy).
- **A backup of the master key.** It encrypts every stored API key. Lose it
  and the database is useless.

The threat model is in [security](security.md), and every variable is in
[configuration](configuration.md).

## Pick a platform

| Platform | How | Persistent storage | Rough cost a month | HTTPS |
|---|---|---|---|---|
| [Railway](deploy-railway.md) | Dashboard, template button, or CLI | Railway volume | Usage based, on the Hobby plan | Automatic |
| [Render](#render) | Deploy button ([render.yaml](../render.yaml)) | 1 GB disk, paid instance only | About $7 (Starter, `0.5c-512mb`) plus about $0.25 per GB of disk | Automatic |
| [Fly.io](#flyio) | `fly` CLI ([fly.toml](../fly.toml)) | 1 GB volume | A few dollars (`shared-cpu-1x`, 512 MB) | Automatic |
| [DigitalOcean (Droplet)](#digitalocean-and-hetzner) | Script from your machine | Droplet disk | $6 (`s-1vcpu-1gb`), or $4 (`s-1vcpu-512mb-10gb`) | Caddy, Let's Encrypt |
| [Hetzner Cloud](#digitalocean-and-hetzner) | Script from your machine | Server disk | From about €5 | Caddy, Let's Encrypt |
| [Any Linux VPS](#any-server) | One line installer, or cloud-init | Server disk | Whatever the server costs | Caddy, Let's Encrypt |
| [Coolify or Dokploy](#coolify-and-dokploy) | Docker Compose resource | Named Docker volume | Whatever the server costs | Their proxy, Let's Encrypt |
| Your own machine | `docker compose up -d` | Named Docker volume | Free | None by default; keep it local or put a proxy in front |

Prices change; check the provider before you pick. Two platforms are left
out on purpose:

- **DigitalOcean App Platform** has no persistent volumes ("App Platform does
  not currently support volumes",
  [DigitalOcean docs](https://docs.digitalocean.com/products/app-platform/how-to/store-data/)),
  so on DigitalOcean Acnologia runs on a Droplet.
- **Koyeb** volumes are a public preview, in a few regions and meant for
  testing only. Not recommended until that changes.

## One click

### Render

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/sidharthpunathil/acnologia)

The button reads the Blueprint in [render.yaml](../render.yaml) and creates
one web service built from the `Dockerfile`, on the `0.5c-512mb` (Starter)
plan, with a 1 GB disk at `/data` and a health check on `/healthz`. Disks
need a paid instance: the free type has no disk.

What the Blueprint sets for you:

- `ACNOLOGIA_MASTER_KEY` and `ACNOLOGIA_ACCESS_PASSWORD` are generated by
  Render. A generated value is a random 256-bit value in base64, which is
  exactly the master key format.
- `ACNOLOGIA_REQUIRE_ACCESS_PASSWORD`, `ACNOLOGIA_SECURE_COOKIES` and
  `ACNOLOGIA_TRUST_PROXY_HEADERS` are `true`.
- It asks you for `ACNOLOGIA_PUBLIC_URL` and `ANTHROPIC_API_KEY` (optional:
  leave it empty to keep the AI features off).
- `ACNOLOGIA_IMAGE_USER=root`. Render mounts the disk owned by root, and the
  image's nonroot user could not write to it. Render passes environment
  variables to the Docker build as build arguments, so this builds an image
  that runs as root.
- Auto deploy is off. You choose when to upgrade, with Manual Deploy.

A service with a disk runs as exactly one instance and loses zero downtime
deploys: each deploy has a short gap while the disk moves to the new
instance.

After the first deploy:

1. Open the Environment tab and copy `ACNOLOGIA_MASTER_KEY` and
   `ACNOLOGIA_ACCESS_PASSWORD` into your password manager.
2. Set `ACNOLOGIA_PUBLIC_URL` to the `https://<name>.onrender.com` address,
   or your custom domain once it is added, with no trailing slash.

Deploying from a private fork works only if the Render GitHub App can see
that repo.

### Fly.io

[fly.toml](../fly.toml) describes one Machine built from the `Dockerfile`,
with a 1 GB volume at `/data`, HTTPS forced and the machine kept running
(the health checks and the provider refresh run inside the process).

```
fly launch --copy-config --no-deploy     # pick an app name and region
fly secrets set ACNOLOGIA_MASTER_KEY="$(openssl rand -base64 32)" \
  ACNOLOGIA_ACCESS_PASSWORD="$(openssl rand -base64 24)"
fly deploy
fly scale count 1                        # SQLite: never more than one
```

Fly never shows a secret again, so to keep copies, generate the two values
with `openssl rand` first, save them in your password manager, and pass
them to `fly secrets set`. Then set `ACNOLOGIA_PUBLIC_URL` to
`https://<app>.fly.dev`, or your domain, under `[env]` in `fly.toml`, and
run `fly deploy` again.

If the server logs `permission denied` on `/data`, uncomment the
`[build.args]` block in `fly.toml` (`ACNOLOGIA_IMAGE_USER = "root"`) and
deploy again. Fly normally hands the volume to the image's user, so most
deploys do not need it.

A Fly volume belongs to a single machine and is not replicated. Fly takes a
snapshot of it daily by default; list them with `fly volumes snapshots list
<volume-id>`, and keep your own database backup as well.

### DigitalOcean and Hetzner

One command from your machine creates the server, a firewall for ports 22,
80 and 443, uploads your SSH key, and runs the installer through cloud-init:

```
doctl auth init
deploy/digitalocean.sh --domain key.example.com --email you@example.com

hcloud context create acnologia
deploy/hetzner.sh --domain key.example.com --email you@example.com
```

- [deploy/digitalocean.sh](../deploy/digitalocean.sh) makes an
  `s-1vcpu-1gb` Droplet by default (`--size s-1vcpu-512mb-10gb` for the $4
  one) and turns on weekly Droplet backups unless you pass `--no-backups`.
- [deploy/hetzner.sh](../deploy/hetzner.sh) tries `cx23`, `cax11` (Arm) and
  `cpx12` in turn, because the cheap types sell out now and then. `--type`
  picks one.

Options, DNS and upgrades are in [Deploying on a server](deploy-vps.md).

### Any server

On any Linux server with root access, the installer sets up Docker,
Acnologia and Caddy with a Let's Encrypt certificate:

```
curl -fsSL https://raw.githubusercontent.com/sidharthpunathil/acnologia/main/deploy/install-server.sh \
  | sudo bash -s -- --domain key.example.com --email you@example.com
```

It writes `/opt/acnologia/.env` once, with a random master key and access
password, and never overwrites it. With no `--domain` it serves
`https://<public-ip>.sslip.io`. Run it again to upgrade.

On a cloud that takes cloud-init user data, paste
[deploy/cloud-init.yaml](../deploy/cloud-init.yaml) when you create the
server and it runs the same installer on first boot. Details in
[Deploying on a server](deploy-vps.md).

### Coolify and Dokploy

Add the repo as a Docker Compose resource and point it at
[docker-compose.yml](../docker-compose.yml). The compose file already
mounts a named volume at `/data` (`cogito-data`, a name kept from before the
rename). Set the variables from [.env.example](../.env.example) in the
resource's environment settings, including the ones under
[Settings for any public deploy](#settings-for-any-public-deploy), and attach
your domain there so their proxy handles HTTPS.

## The container image

`ghcr.io/sidharthpunathil/acnologia` is built by
[release-image.yml](../.github/workflows/release-image.yml) for `linux/amd64`
and `linux/arm64`.

| Tag | What it is |
|---|---|
| `latest` | The newest release. Until the first release exists, it follows `main`. |
| `main` | Every push to `main`. |
| `X.Y.Z` | A release, from a `vX.Y.Z` tag. |
| `sha-xxxxxxx` | One commit. |

To run it anywhere Docker runs:

```
docker run -d -p 8080:8080 -v acnologia-data:/data \
  -e ACNOLOGIA_DATA_DIR=/data --env-file .env \
  ghcr.io/sidharthpunathil/acnologia:latest
```

The image already sets `ACNOLOGIA_DATA_DIR=/data`; the `-e` keeps a
`ACNOLOGIA_DATA_DIR=./data` line copied from `.env.example` from moving the
data off the volume. The image is distroless and runs as a nonroot user
(uid 65532).

## Settings for any public deploy

| Variable | Value |
|---|---|
| `ACNOLOGIA_ACCESS_PASSWORD` | A long random password, 12 characters at least. `openssl rand -base64 24` makes one. |
| `ACNOLOGIA_REQUIRE_ACCESS_PASSWORD` | `true`: the site never comes up unlocked. With no password set, one is generated into `/data/access-password`. |
| `ACNOLOGIA_MASTER_KEY` | 32 bytes, base64 or hex: `openssl rand -base64 32` or `acnologia gen-master-key`. If unset, a key is generated into `/data/master.key` on first boot. |
| `ACNOLOGIA_PUBLIC_URL` | The address people use, such as `https://key.example.com`, no trailing slash. Needed for sharing with other servers and for `acn login`. |
| `ACNOLOGIA_SECURE_COOKIES` | `true` behind HTTPS. |
| `ACNOLOGIA_TRUST_PROXY_HEADERS` | `true` only behind a proxy that overwrites `X-Forwarded-For`. Every platform on this page does. |
| `ANTHROPIC_API_KEY` | Optional: turns on the Assistant, the provider builder, Fill with AI and the provider refresh. |

Leave `ACNOLOGIA_ADDR` unset on Railway and Render: the server listens on
`0.0.0.0:$PORT` when the host sets `PORT`. `fly.toml` sets it to `:8080` to
match `internal_port`.

## After the first deploy

1. **Open the site.** The lock screen asks for the access password.
2. **Unlock it.** With the default `ACNOLOGIA_ACCESS_SIGNS_IN=true`, the
   access password is the whole login and you land in the dashboard as the
   owner.
3. **Save the master key** in your password manager: from the platform's
   variables, from `/opt/acnologia/.env` on a VPS, or from `/data/master.key`
   if you never set one. Store it apart from any database backup.
4. **Set `ACNOLOGIA_PUBLIC_URL`** to the final address and redeploy.
5. **Add a custom domain** if you want one, then update
   `ACNOLOGIA_PUBLIC_URL` to match.
6. **Set up backups** of `/data/acnologia.db` (with its `-wal` file, or with
   the service stopped), or use the platform's volume snapshots.
7. **Plan upgrades.** Render: Manual Deploy. Fly: `fly deploy`. Railway:
   a push to the connected branch, or Redeploy. VPS: rerun the installer. Back up first.
